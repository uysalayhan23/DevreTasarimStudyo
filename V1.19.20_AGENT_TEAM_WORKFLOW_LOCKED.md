## 1. Temel kural

Zorunlu zincir:

**1. LİDER UZMAN → 2. ÇAPRAZ UZMAN → 3. MQ-12 TEST KANITI → 4. MQ-13 REPO SÜREKLİLİK → 5. MQ-00 TEKNİK DİREKTÖR KARARI**

Bu beş adım ilgili iş için uygulanmadan durum **DONE** olamaz.

## 2. İş paketi açılışı

Her yeni iş bir WP veya mevcut MQ ID'sine bağlanır.

Başlangıç kaydı:
- ID,
- problem,
- kanıt,
- öncelik,
- lider ajan,
- çapraz doğrulayıcı,
- etkilenen dosyalar,
- bağımlılıklar,
- hedef test,
- regresyon kapsamı,
- fiziksel/pedagojik etki,
- rollback riski,
- DONE kriteri.

Aynı problem için ikinci ID açılmaz.

## 3. Aşama A — Lider uzman incelemesi

Lider uzman:
- mevcut davranışı kanıtlar,
- kök nedeni belirler,
- güvenilir kaynak gerekip gerekmediğini belirler,
- çözüm tasarımını yazar,
- değişecek dosyaları sınırlar,
- test ihtiyacını belirler.

Tahmin, uydurma fiziksel veri veya “muhtemelen” gerekçesiyle üretim değişikliği yapılmaz.

## 4. Aşama B — Çapraz uzman doğrulaması

İkinci uzman liderin çözümünü aynı açıdan tekrar etmez; farklı risk açısından kontrol eder.

Örnek:
- fiziksel ölçü → terminal/geometri,
- control/material görsel ölçeği → doğrulanmış fiziksel W/H oranı + scene/mm tutarlılığı + aspect distortion audit,
- simülasyon → pedagojik enerji akışı,
- save/load → eski proje/migration,
- UI → browser/regresyon,
- asset → kaynak/orientation,
- CI → repo süreklilik.

Çapraz uzman:
- yanlış varsayım,
- yan etki,
- eksik dosya,
- eski proje riski,
- test boşluğu
bulursa iş FIXING/AUDIT durumunda kalır.

## 7. Aşama E — MQ-13 GitHub/repo süreklilik kontrolü

MQ-13 **non-blocking destek ajanıdır**; rutin işi yavaşlatmaz.

Her iş sonunda kontrol eder:
- doğru branch `v1.19.20`,
- kilitli eski refler değişmedi,
- gereksiz branch oluşmadı,
- dosya doğru klasörde,
- import/path kırılmadı,
- package kapsamı doğru,
- durum/operasyon kaydı güncel,
- aynı dosyanın gereksiz kopyası oluşmadı,
- bir sonraki oturumun nereden devam edeceği açık.

Kritik olmayan repo düzeni konusu işi bloke etmez; backlog'a alınır.
Veri kaybı, yanlış branch, kırık path, kilitli ref veya paket dışı kritik dosya varsa MQ-00'a yükseltilir.

## 13. Audit metodolojisi

Yeni kalite gözden geçirmelerinde:
1. tek Master taraması başlangıç envanteri üretir,
2. ilgili uzman bağımsız geçiş yapar,
3. ikinci uzman farklı risk açısından çapraz kontrol eder,
4. MQ-12 testlerin gerçekten davranışı doğruladığını kontrol eder,
5. MQ-13 repo/CI/paket sürekliliğini kontrol eder,
6. MQ-00 yanlış pozitifleri ayıklar ve nihai listeyi yayınlar.

Bu, v3 auditinde doğrulanan kalıcı yöntemdir.
